# Activation lifecycle (Kimi)

- Native identity is `session_id` on hook stdin. Resume keeps the same id; `/fork` creates a new id (`state.forkedFrom`) that does not inherit the binding. A fork that invokes `/mindie-agent` gets its own independent binding with its own capture boundary — never the parent's capability, job ownership or collectable history.
- `/mindie-agent` reaches the adapter as a native `skill_activation` origin (the TUI user-slash form, or an in-turn `model-tool` activation after the host resolves the user's `/mindie-agent` prompt — the latter only when the turn-opening user text actually invokes the entry) or as a legacy `plugin_command` origin (`:init` alias). Plain mentions, injected content, same-named foreign skills and inherited fork history never match.
- Slash control is one `mindie_entry` MCP call bound by PreToolUse nonce. The current turn-opening origin must be the verified entry. `activationId` is consumed once. Older matching commands are ignored. Caller task IDs are rejected.
- New choices are `contribute` or `disabled`; saved `read-only` and `later` values remain off and are not offered as new commands. A first contribution choice can be conversational (public `owner/repo` + account in the user's own reply, then `op=choose`) or native (`/mindie-agent contribute owner/repo ACCOUNT`). Change a saved choice, including a legacy `contribute` that needs migration, through the native entry; `/mindie-agent disabled` turns both contribution paths off. Explicit entry arguments are the user's choice and need no second confirmation. When the user explicitly enables community contribution for a target public knowledge repository `owner/repo` (such as `mindie-agent/knowledge-vllm-ascend`), reuse or create the personal fork of that target knowledge repository as needed via the authenticated `gh` channel (`gh repo fork owner/repo --clone=false`) and bind the user's personal Fork `ACCOUNT/repo` (`--community-fork ACCOUNT/repo`).
- There is no `sessionStart` Skill. TurnStarted only records `turn_id`; it does not replay commands.
- The persistent choice lives in the profile-shared consent document (`mindie-consent.json`, schema `mindie-consent/1`), serving as the single unified authority for both community knowledge sharing and automatic sanitized tool fault reporting; the community settings file (`mindie-community-config/1`) carries the project scope and points at that authority.
- Unified consent & upgrade boundary: explicitly choosing `contribute` configures public knowledge sharing and starts the native background fault-reporting worker; choosing `disabled` turns both off and withdraws unsent reports. Existing `disabled`, `later`, and `read-only` records remain off across upgrades. Legacy knowledge-only `contribute` records lacking the unified consent revision (`choice_revision` / `needs_choice`) do not automatically gain fault-upload permission on upgrade or startup until the user explicitly confirms the unified choice once.
- Three-state separation: keep (1) local consent configuration written, (2) background organizer/reporter worker running, and (3) external GitHub Issue or knowledge PR created strictly distinct. Never report a saved local config or queued event as a running worker or published Issue/PR; inspect worker and queue state via `/mindie-agent:reporting-status` (read-only).
- The per-task lease is an internal binding established by the entry — not a consent step. It has no failure pause: ordinary failures never require deactivate/reactivate.
- **Multi-Domain Route Registration, Target-Domain Activation & Bare `deactivate` Semantics**:
  - Registering an additional domain Engine/Feed in an existing adapter config uses `python -m mindie_knowledge.loop.domain_routes register --adapter-config <path> --domain <domain> --engine-config <path>`, which updates `domain_configs` (preserving `default_domain`) and **never** creates or widens `consent`.
  - Ordinary reads (`knowledge_query(domain=..., request_nonce=...)`, `knowledge_explain(ref="mindie://<domain>/...", request_nonce=...)`) do not widen authorization. Distilling or contributing to a registered target `domain` requires that target domain's own existing `consent` and `project_root` scope plus explicit target activation via `mindie_entry(op="init", domain="<domain>", request_nonce=...)` (which binds only the target domain's lease without replacing the default session binding).
  - Explicit `/mindie-agent:deactivate` / `mindie_entry(op="deactivate", request_nonce=...)` revokes **only the current `session_id`** across the default domain and all registered `domain_configs` (never revoking other sessions). If any registered domain fails or times out during revocation, `status="partial"` is returned while preserving `changed` and per-domain outcomes (`domains[]`), reporting partial failure and already-revoked side effects separately.
- Stop capture is gated: live binding, sharing on, cwd in scope, claim first=True. Only a bound task with sharing ON durably hands off material and may wake the capture service; sharing OFF does not start it. A knowledge query restoring its own service is a separate read path.
- **Single-Turn `Stop` != Long-Horizon Task Completion**: A Kimi `Stop` event only marks the end of the current model turn and hands off that turn's transcript slice when eligible. It never implies that a multi-step engineering task, remote NPU benchmark, or iterative optimization loop is finished; verify remote job completion (`remote_job_status`), `Run Manifest` artifacts, and ledger evidence (`PROGRESS.md` / `experiment-ledger.jsonl`) before concluding a long-horizon task.
- MCP: 0.42.0 tools/call has no session `_meta`. PreToolUse binds `request_nonce` to exact tool + arguments + `tool_call_id`.
- Sharing status shows a problem. A transient local or network failure is recovered by the existing worker — a deadline-interrupted region gets one bounded background recovery, not a contribution batch command or another model turn. Authentication, trust, rejected content, or invalid configuration can need an explicit user or operator action. Batch inspection is optional troubleshooting, not a recovery step.
