# Diagnostic Reasoning, Exploration & Verification Workflows

Use these engineering guidelines when diagnosing accuracy or performance issues, designing discriminating experiments, or running multi-node bring-up and PR delivery workflows.

## 1. Discriminating Experiments & First Divergence

- **Formulate testable hypotheses**: State the open question, competing explanations, and the lowest-cost observation that separates them (source check, boundary probe, minimal reproducer, or controlled run). Finding the first divergent layer or excluding a cause counts as progress even before the end-to-end test passes.
- **Locate the first divergent boundary**: Align logical inputs, tokens, states, stages, and ranks before comparing tensors. Check shape, dtype, stride, ownership, and readiness right at the boundary where values first diverge.
- **Disaggregated (P/D) KV handoff**: Do not rely on hook names (`wait_for_layer_load`, `start_load_kv`) or scheduler counters (`num_computed_tokens`) as proof that remote KV arrived. Dump consumer tensors only after the layer's wait and relocation finish, immediately before the first consuming operator. To detect missing transfer bytes or stride mismatches (`(N-1)*stride + valid_bytes`), pre-fill exclusively owned destination blocks with a dtype-safe sentinel (`NaN` for float, extreme finite values for quantized caches), without modifying shared prefix-cache blocks or page-shared views (`layer_stride == 0`).
- **Upfront subgraph fusion analysis (Phase 0)**: Before micro-tuning an isolated kernel, identify fusable producer-consumer chains (eliminating GM round-trips and standalone `pack`/`cast`/`quant` ops), hard non-fusable boundaries (collectives, `L1`/`UB` capacity limits, full-reduction normalizations), and critical-path overlap (`max(P+C, Q+G)`). Use the `G0–G3` qualification gate ladder when available.

## 2. Observer Controls, Stateful Reproducers & Independent Oracles

- **Account for observer effects**: Debug dumps, clones, `isfinite` checks, and stream syncs can alter timing or memory lifetimes. If instrumentation changes the failure mode, compare the uninstrumented baseline against an observer-only control and verify the final fix with debug instrumentation removed.
- **Stateful and concurrent reproducers**: Capture input, initial state, and request scheduling sequence together. Compare fresh vs. history-exposed processes, and preserve concurrency when diagnosing race or pool-reuse bugs.
- **Independent oracles**: Validate against a reference path that does not share the suspected bug. In disaggregated serving, an HTTP 200 response can mask a failed remote KV pull that fell back to local prefill recomputation—always verify non-zero transferred KV bytes and zero recompute fallback alongside output quality (`repeated_ngram`, `punctuation_run`, `immediate_eos`). When features like `batch_invariant`, `enable_fused_mc2`, prefix cache, `ACLGraph`, `MTP`, or `PCP/DCP` are active, run a `2×2` `(Colocated vs Disaggregated) × (Feature Off vs On)` check to isolate the fault.

## 3. Scale Verification, Baseline Parity & PR Delivery Workflows (`W1–W7`, `C1–C5`)

1. **Progressive verification ladder & pruned-vs-full weight boundary (`W1`)**:
   - Advance through `Single-Op → 1-Node Pruned Weights / 2-Node Minimal Topology → 4-Node Full Weights → Immediate Cluster Release`.
   - On 1-node pruned weights (e.g., 16 experts), verify: (a) operator/weight loading, (b) KV Cache grouping and `build()` count, (c) minimal 2-bucket `ACLGraph` capture covering boundary shapes, (d) non-zero execution and acceptance rate on quantized/speculative paths, and (e) Peak Activation memory parity against baseline.
   - On 4-node full weights, run historical regression cases, benchmark datasets (e.g., GPQA), speculative acceptance rate, and SLA sweeps, then release the multi-node cluster immediately. Downscale 4-node or long-context bugs to 1–2 nodes whenever reproducible.
2. **Same-topology baseline A/B diff & three-axis migration parity (`W2`)**:
   - Lock the last known-good baseline commit first. When operator kernels are unchanged, focus on framework glue (`ModelRunner`, `AttentionMetadataBuilder`, KV Cache Specs, Weight Loader).
   - Compare baseline vs. candidate side-by-side on identical topology (`0..7` vs. `8..15` with matching `TP` and `block_size`), verifying parity across **(a) numerical accuracy**, **(b) Peak Activation memory**, and **(c) speculative acceptance rate**.
3. **Upstream/sibling-first implementation & pre-review audit (`W3`)**:
   - Reuse native upstream `vllm` hooks (`process_weights_after_loading`, custom ops) and mature `vllm-ascend` sibling patterns (`AttentionMetadataBuilder`, `common` base classes). Before review or after a rebase, audit diffs line-by-line to remove debug artifacts and check blast radius on shared runner/KV-cache files.
4. **Speculative graph alignment, out-of-graph metadata & SLA sweep (`W4`)**:
   - For `K`-step speculative decoding (DSpark/MTP), align `ACLGraph` capture buckets to multiples of `K+1`, select graphs by padded `num_input_tokens`, and keep buffer allocation and tiling/sink metadata construction outside the captured graph while eliminating host D2H syncs (`seq_lens`, `num_accepted_tokens`). Validate `greedy` before `probabilistic` sampling.
   - Run SLA sweeps on ~95% prefix-cache datasets (`1K` output, power-of-2 inputs `2K → 256K`, per-DP concurrency `1, 2, 4...` under `TPOT <= 30ms`), reporting `TPOT`, `ITL (p50/p90)`, and `mean_acceptance_length`.
5. **Parent + atomic child PR stack & lightweight pre-flight (`W5–W6`)**:
   - Maintain **1 parent integration PR** for multi-node E2E verification and split orthogonal features into an ordered stack of **atomic child PRs** with `< 5 min` reduced-weight/dummy-weight smoke tests.
   - Run a 4-point pre-flight check: (a) parallel C++ builds (`-j` / `MAX_JOBS`) + `ASCEND_CUSTOM_OPP_PATH` `.so` check, (b) explicit `VLLM_VERSION` pin, (c) `GLOO/HCCL_SOCKET_IFNAME`, and (d) benchmark client running inside the remote container rather than over VPN.
6. **Custom-op ABI/counting-domain, hang triage, Safetensors preflight & hybrid profiler segmentation (`C1–C4`)**:
   - **Custom-op ABI & counting domain (`C1`)**: On `ACLNN_ERR_PARAM_NULLPTR (161001)` or `561000`/`561103`, check `opapi_math` / `libopapi.so` symbol shadowing and CANN ABI consistency (`ldd`/`nm -D`), and register both `PrivateUse1` and `Meta` kernels. For `npu_fused_infer_attention_score_v2` (`FIA`) `errcode 264` in MTP (`step >= 1`), match `actual_seq_lengths_kv` counting domain to tensor rank (`3D BSH/BSND` cumulative tokens vs. `4D BNSD` sequence count). Pad non-32B-aligned `head_dim` (e.g., `35 -> 48`) before launch and slice back to `[:35]`. Clear `.torchair_cache` and `~/.cache/vllm/torch_compile_cache` after C++/graph-pass edits.
   - **Disk `D`-state vs. NPU hang & thread NPU context (`C2`)**: When multi-card launch shows `0%` AICore utilization, check `/proc/<pid>/status` (`State`) and `/proc/<pid>/wchan` first—`D` state in `lock_page_killable`/`nfs_*`/`folio_wait*` is storage I/O wait, not an HCCL deadlock. If `/v1/models` succeeds while `/v1/chat/completions` hangs, inspect `shm_broadcast`/`MessageQueue` ring buffers and ZMQ framing. On `107002`/`507001`, check earlier logs for `camem` swallowed `207001` OOMs. Call `torch.npu.set_device(device_id)` in every `ThreadPoolExecutor`/ZMQ callback thread (`107003`).
   - **Zero-NPU Safetensors preflight & GDN/KDA/DCP invariants (`C3`)**: Inspect `.safetensors` headers (`inspect_safetensors_checkpoint`) before acquiring NPU leases to catch truncated shards or unquantized `BF16` experts in W8A8 checkpoints. In hybrid linear attention (`GDN`/`KDA`), avoid double $1/\sqrt{d}$ query scaling across chunked prefill and index final states by `actual_seq_lengths_q` without overwriting recurrent caches during draft steps. In Ring/Ulysses/DCP attention, merge cross-rank LSE in `float32` natural-log domain (`lse = m + log(l)`).
   - **Hybrid Dense + MoE + MTP profiler segmentation (`C4`)**: Select the primary compute `streamId` by `argmax_s sum(duration_ns)`, keep `MlaPrologV3` and `KvQuantSparseFlashAttention` inside one MLA layer, and group `Dense prefix + MoE trunk + MTP draft` layers into a single decode step.
7. **DiT (`MindIE-SD`) & multi-stage Omni (`vllm-omni`) workflows (`W7`, `C5`)**:
   - **Two-stage integration (`API-first, then torch.compile`), DiT-only multirank probe & $c/f$ comm-masking (`W7`)**: Verify Stage 1 eager API substitution and precision before Stage 2 `torch_npu._inductor` pattern passes (`PatternMatcherPass` + `register_replacement` with layout/alignment guards and `_pattern_pass = True`). Profile multi-card DiT (`Ulysses`/`Ring`/`CFG`) with a DiT-only few-step protocol (`3–5` warmup + `3–5` measured steps) before 50-step E2E runs. Check $S_{\text{max}} \le 1 / (1 - c/f)$ ($c/f \ge 10\%$) before multi-stream overlap, and watch for A2/A3 package power capping (`aicore_freq` drop) when `FlashAttention` overlaps `HCCL AllToAll` at `seq_len / sp_size < 4096`. Use Window A/B/A interleaved timing and 3-tier accuracy gates (`PSNR >= 35 dB` + `SSIM >= 0.98` + `LPIPS <= 0.02` lossless; `PSNR >= 26 dB` + `SSIM >= 0.88` lossy).
   - **VAE latent-boundary slicing, quantization alignment & Omni streaming (`C5`)**: Slice video VAE (`Wan2.2`/`TAEHV`) strictly along latent spatial/temporal boundaries while carrying causal `feat_cache` ring buffers across chunks (`clear_cache()` at request end). In quantized weights (`W8A8_DYNAMIC`/`TIMESTEP`/`FP8`/`MXFP8`), enforce 32/64-byte alignment rather than `.numel() * element_size()` on packed/NZ tensors. For `vllm-omni` (`Thinker -> Talker -> Code2Wav`), separate `TTFP` vs. `RTF`, enable `async_chunk: true` (`codec_chunk_frames: 25`, `codec_left_context_frames: 25`), keep `NPUARModelRunner` decode at static `[batch_size, 1]` with `max_num_seqs: 1` on Talker/CodePredictor stages, and ensure custom `OmniConnector` (`Mooncake`/`Yuanrong`/`SHM`) adapters implement `put`/`get`/`cleanup`.
