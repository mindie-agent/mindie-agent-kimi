# 整理器故障分类与进程组管理

<b>中文</b> | <a href="organizer-diagnostics.en.md">English</a> · <a href="README.md">返回文档索引</a>

当用户开启社区经验贡献后，`mindie-agent-kimi` 会调用本地 Kimi CLI 整理器（Organizer）在隔离环境中生成分块标题与摘要。本文说明整理器的静态退出分类与进程组生命周期管理契约。

---

## 1. 隔离调用与静态错误分类

- **纯净隔离配置**：整理器在独立的临时配置目录下运行，不加载业务会话的插件、Skill、Hook 或 MCP 服务，执行完成后自动清理临时目录。
- **静态阶段退出码**：配置缺失、输入不合法、原生调用失败、输出格式非法、输出超限与超时（内部 120 秒 / 外层 125 秒有界超时）均映射为共享契约中的静态分类码。
- **敏感信息零残留**：共享核心仅记录静态错误分类、退出码与耗时秒数，绝不将服务商原始标准错误输出（stderr）、会话正文或环境变量写入持久化诊断记录。单次失败输入绝不自动重放。

---

## 2. 进程组归属与干净回收

- **统一进程组管理**：整理器与其拉起的原生 Kimi 子进程运行在核心托管的同一进程组内；无论是正常返回、超时还是被核心取消，核心都会在终态路径上关闭整个进程组，确保不会遗留孤儿进程。
- **验证覆盖**：已在 macOS 实机环境下验证全套 7 类退出分支（配置、输入、原生异常、非法结果、输出超限、120 秒超时与正常完成）及隔离 K3 模型调用，确认取消耗时约 0.95 秒、正常退出与取消后均无残留子进程。
