# 整理器故障分类与进程组管理

<b>中文</b> | <a href="organizer-diagnostics.en.md">English</a> · <a href="README.md">返回文档索引</a>

当用户开启社区经验贡献后，`mindie-agent-kimi` 会调用本地 Kimi CLI 整理器（Summary Worker）在隔离环境中为脱敏后的公开材料块生成索引标题与摘要。本文说明整理器的静态分类、结果回执与进程组生命周期管理契约。

---

## 1. 摘要工作者协议与静态错误分类

- **共享线协议**：共享核心先以 `--identity` 调用整理器获取带指纹的策略身份（模型、实现哈希、限额），随后通过标准输入发送唯一请求，并期望标准输出返回唯一严格结果信封（`mindie-summary-outcome/1`）。退出码为零只表示信封已送达，不代表索引成功；失败与不确定的计费结果也会以显式信封返回，绝不以空结果冒充成功。
- **纯净隔离配置**：整理器在独立的临时 `KIMI_CODE_HOME` 下运行，不加载业务会话的插件、Skill、Hook 或 MCP 服务，执行完成后自动清理临时目录。Provider 与模型来自用户所选原生配置，缺失模型或宿主是配置失败，绝不是默认值或空成功。
- **静态分类**：配置缺失、请求不合法、原生调用失败、输出格式非法、输出超限与适配层自有有界截止（300 秒）均映射为共享契约中的静态分类与原因码；核心不再为工作者施加总超时。
- **敏感信息零残留与计费诚实**：Kimi 提示模式不回报用量计数，因此一次已发起的模型调用记为 `model_calls=1`、`usage_known=false`（账单状态 unknown），绝不记零。共享核心仅记录静态错误分类、原因码与耗时，绝不将服务商原始标准错误输出（stderr）、会话正文或环境变量写入持久化诊断记录。失败或不确定的付费请求绝不自动重放，也不替换兜底摘要。

---

## 2. 进程组归属与干净回收

- **统一进程组管理**：整理器与其拉起的原生 Kimi 子进程运行在核心托管的同一进程组内；无论是正常返回、超时还是被核心取消，核心都会在终态路径上关闭整个进程组，确保不会遗留孤儿进程。
- **验证覆盖**：单元测试覆盖身份指纹、缺失配置、缺失宿主、线协议非法输入、策略漂移、完成但无可用答案以及完整往返（桩二进制）等分支；macOS 实机验收覆盖原生 K3 调用、取消与无残留子进程。
