# mindie-agent-kimi 0.1.26: Storage Lifecycle Governance and Legacy Reclamation

- Component locks updated: `mindie-coordinator 0.7.11`, `mindie-debugger 0.1.3`, `mindie-diagnostics 0.5.14`, `mindie-knowledge 0.13.22`, `mindie-profiler 0.5.15`, `mindie-sim 0.9.15`, and `remote-dev 0.11.12`. `runtime-requirements.txt` remains the immutable bootstrap baseline; only `runtime/active-overrides.txt` changes.
- Plugin upgrades no longer build two complete `.venv` trees. When a usable current runtime interpreter exists, the updater extracts the `generations/<sha>` source tree first, then reuses that interpreter for component discovery and the merged build; `generations/<sha>/.venv` is built only when no merged component build is needed or no current interpreter is available (cold start). A same-volume managed uv cache avoids cross-volume copy inflation.
- A failed staging step reclaims the orphan `launch/<sha>` and unpublished half-built `generations/<sha>` created by that attempt, so 49+ orphan launchers no longer accumulate.
- Scheduled/background updates silently run the shared legacy sweep both before a build and after a successful switch. They reclaim 68+ `component-runtimes`, 34+ `generations`, 49+ `launch`, 33+ `receipts`, and abandoned `mindie-kimi-summary-*` scratch roots left by timeouts or forced kills, while strictly retaining the current generation, the `previous` rollback generation, `bootstrap` / `bootstrap-venv`, generations still referenced by an external plist/wrapper, live leases, and cross-plugin borrowed roots.
- After a component hot update or a plugin switch commit, the updater atomically refreshes the installed `mindie-front`, Kimi's managed plugin manifest, the `originalSource` recorded in `installed.json`, and the macOS LaunchAgent / Windows scheduled-task wrapper. Only already-existing, recognizably MindIE-owned files are updated; the user's scheduling choice is never changed.
- The resident MCP service holds the shared runtime lease of its owning generation for its whole lifecycle. Summary isolation directories now use the owner-PID-marked shared `summary_scratch` and are deterministically removed in `finally`.
- A local contention failure in post-switch host refresh or storage reclamation is recorded as a structured `receipt_warning` / `cleanup_warning`. It never rolls back the committed generation and never writes a one-way `fault` lockout.

Shared components: [mindie-knowledge 0.13.22](https://github.com/mindie-agent/knowledge/releases/tag/v0.13.22), [remote-dev 0.11.12](https://github.com/mindie-agent/remote-dev/releases/tag/v0.11.12), [mindie-diagnostics 0.5.14](https://github.com/mindie-agent/diagnostics/releases/tag/v0.5.14).
