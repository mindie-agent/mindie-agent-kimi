# mindie-agent-kimi 0.1.33: Windows-Safe `uv` Launch, 9-Domain Knowledge Binding & Authoritative `kimi.json` Precedence

[中文](mindie-agent-kimi-0.1.33.md)

- **Canonical 9-package `pyproject.toml`, `uv.lock`, and `product-contract.json` (`1,194 <= 1,200` `scripts/*.py` LOC)**: Adds root `pyproject.toml`, `uv.lock`, and `product-contract.json` pinning all 9 runtime packages (including `mindie-harness >= 0.1.5` and `npu-top 0.3.5`, synchronized with `runtime-requirements.txt` and `runtime/active-overrides.txt`) within the 6-file `scripts/*.py` budget while serving `serverInfo.version == "0.1.33"`.
- **Eliminate bare `python3` `WindowsApps` stub hazards**: Migrates `kimi.plugin.json` MCP servers (`knowledge`, `remote`, `components`) and hooks (`PreToolUse`, `Stop`) from bare `python3` to `uv run --no-project --python 3.13 python -B -X utf8 ./scripts/mindie_launch.py ...`, and updates `mindie_launch.py` and `install_kimi_plugin.py` to reject Microsoft Store `WindowsApps` 0-byte Python stubs (`\windowsapps\` and `st_size == 0`).
- **Validated `kimi.json` precedence & safe `MindIEKimiUpdate` retirement**: `mindie_launch.py` prefers a validated canonical `kimi.json` (`component_release/runtime.json` or usable `python`) over stale `update/current.json` records (falling back to `update/current.json` only when `kimi.json` is absent or its interpreter is missing); `setup.py init` and `setup.py update` safely query and delete legacy `MindIEKimiUpdate` Windows scheduled tasks (and macOS `launchd` / Linux `systemd` equivalents) before unlinking old `.pyw`/`.xml` wrappers.
- **Content-addressed 9-domain bindings & honest `Stop` capture**: Replaces bespoke single-domain engine builders in `setup.py` and `entry.py` with `ensure_knowledge_binding(..., already_locked=True)` under `.kimi.json.update.lock` across all 9 public Ascend domains (`engines/kimi/<20hex>/<domain>.engine.json` + `domain_configs`, preserving `setup.py init --root`), and delegates `entry.py:_stop` to `run_stop_capture(..., timeout_sec=6.0)` with honest `turn` (`turn_id` + `last_assistant_message`) vs deterministic checkpoint `notification` (`event_id`) identity and permanent `inactive` revocation enforcement.
- **Reusable host acceptance CI gate**: Wires `mindie-agent/mindie-bench/.github/workflows/verify-host-plugin.yml@main` (`host: kimi`) into `.github/workflows/checks.yml` and `release-ready`.
