# mindie-agent-kimi 0.1.31: Five-File Thin Architecture & Installer UX Upgrade

[中文](mindie-agent-kimi-0.1.31.md)

- **The Great Subtraction: `scripts/` keeps only 5 thin files (≤ 1,200 lines total)**: all legacy duplicate runtime modules (`updater*.py`, `bridge.py`, `mcp_server.py`, `organizer*.py`, `sharing.py`, `paths.py`, `kimi_launch.py`, and the rest) are deleted, leaving `mindie_launch.py`, `entry.py`, `kimi_transcript.py`, `install_kimi_plugin.py`, and `setup.py`. Cold start, MCP serving, sharing consent, diagnostics, updates, process supervision, and atomic writes all delegate to the shared [`mindie-harness`](https://github.com/mindie-agent/harness) substrate (`API_VERSION = 1`).
- **One cold-start entrypoint and zero-popup hooks**: all three MCP servers and the `PreToolUse` / `Stop` hooks in `kimi.plugin.json` now invoke `python3 ./scripts/mindie_launch.py`. `hook pretool` returns `{}` immediately without reading stdin; `hook session-start` atomically enqueues `pending-update-check.json`; `hook stop` verifies the `mindie-consent.json` / `mindie-community.json` contribution tier and `project_roots` before opening SQLite, uses `os.path.commonpath` for containment (`/work/app-other` never matches `/work/app`), and exits with zero SQLite when unauthorized or out of scope.
- **Strictly separated MCP tool surfaces**: `knowledge` exposes only the five `knowledge_*` tools; `remote` exposes only the 14 Kimi `remote_*` tools (including `remote_Read`, `remote_Bash`, `remote_probe`, and `remote_auth`); `components` exposes only `mindie_status`, `mindie_doctor`, diagnostics, `profiler`, `sim`, `coordinator`, `debugger`, and the other component tools. Cross-surface calls return `unknown_operation`, and `initialize` reports `serverInfo.version = "0.1.31"`.
- **Upgraded installation and first-use onboarding**: install with `uv run https://github.com/mindie-agent/mindie-agent/releases/latest/download/install.py --host kimi` (`gh` is optional and never a blocker). First use completes three dynamic `AskUserQuestion` steps — workspace, contribution tier (`contribute` when `gh` is signed in, otherwise `local-only`), and an optional one-step SSH NPU connection (with `--password` available at the end of terminal mode) — followed by a `mindie_doctor` readiness check and a polite one-line Star postscript.
- **Non-blocking task continuity rule**: `remote-dev`, `coordinator`, `knowledge_*`, and `mindie_doctor` are accelerators, never roadblocks. If any tool fails, report the concrete error once (reconciling uncertain remote writes before repeating them) and continue immediately via native `ssh` / `scp` or task-local scripts.
- **Docs, CI, and release metadata aligned**: every `used_interfaces` / `code_paths` / `test_ids` entry in `harness-compatibility.json` now points to the five retained scripts, `skills/mindie-agent/SKILL.md`, and the new contract tests; CI validates `entry.verify_bundled_seed()`, `scripts/setup.py release-metadata`, the native Node launch test, and `pytest`; release badges and notes are bumped to `0.1.31`.
