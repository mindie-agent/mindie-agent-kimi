# Acceptance status

Pre-release work, 2026-09-21. The design inherits the [nine MindIE / VAWS principles](https://github.com/mindie-agent/mindie-agent/blob/main/docs/design-principles.md).

Actual native Kimi 0.42.0 with K3 / max verified plugin installation, slash-command activation, first-use choices, a normal subsequent read-only choice, and retrieval plus full-body reading from the real public knowledge repository. Sharing remained off, no capture was created, and no collection turn database was created. Native source and fork records verified exclusion of old or inherited material. These checks preceded the final generation-dispatch changes and do not prove the final updater.

The native organizer ran once with a verified empty tool set and produced useful case content, but review found a summary that confused an initial device setting with the verified final setting. The prompt now separates initial, failed and verified observations, and avoids turning case-specific fields into a mandatory protocol. A later K3 / max run on the locally installed Kimi 2.0.2 reached its 120-second deadline without output. It stopped without automatic retry; the revised prompt's content quality remains unverified.

Local component checks cover task admission, exact nonce binding, replay rejection, parser boundaries, bounded hook/process handling, generation locks, exact native inventory validation and rollback. Native update continuity and the final Stop-to-publication loop require separate evidence. A green component suite is not a native release verdict.

Windows code and task registration remain unverified on a real Windows desktop. The user will provide that environment later. Release-channel tracking and migration of old business Skills remain deferred; current updates track `main`.
